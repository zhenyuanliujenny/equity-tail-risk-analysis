The research problem

A daily return quantile marks a loss threshold, but does not describe the average loss beyond it. This project compares historical VaR with expected shortfall, examines GBM simulation assumptions, and uses GARCH to describe changing volatility.

My work: I was responsible for data acquisition and cleaning, VaR/CVaR analysis, Monte Carlo simulation, GARCH modeling, visualizations and reporting during my Innovation AI internship. The project followed supervisor guidance; the portfolio code is a later refactor of the original methods.

This is a research portfolio. It does not demonstrate a deployed trading bot, working NLP system, or verified trading loss avoidance.

The interpretation matters

A larger VaR–CVaR gap indicates a deeper average loss beyond the threshold. The gap alone does not prove a fat-tailed distribution: normal returns also have a quantile-to-tail-mean gap. The reported tail multiplier is descriptive and should not be treated as a validated trade signal.

GARCH is implemented; advance prediction is not established

The source code fits GARCH(1,1) using Python’s arch library. It displays fitted conditional volatility for GPRO, PLAY and HOFT during historical stress windows. The estimation periods extend through and beyond those displayed windows, so the plots cannot support out-of-sample early-warning claims.

The later PTON action illustration is a separate example: its price bands use a 10-day rolling standard deviation, while sentiment score and action dates are hand-entered annotations. They are not outputs of an NLP pipeline or verified trade execution. That illustration is excluded from the implemented results here.

Limitations and next steps

  • Equities are analyzed individually. No portfolio weights or cross-asset simulation model are implemented in the curated code.
  • Normal-shock GBM and normal-innovation GARCH may miss distributional features; simulation volume does not remove model risk.
  • Retrospective ticker/window selection introduces hindsight and selection bias.
  • Unavailable/delisted tickers and unequal histories can distort cross-equity comparisons.
  • Forecast claims would require rolling estimation, held-out evaluation and benchmark comparisons.
  • NLP, live execution, and loss-avoidance performance need separate implementation and evidence.
